# Design system — V-Energy Grid 360

Catálogo dos componentes reutilizáveis do portal (backlog **V2-02**). Toda tela é montada
com o que está aqui; componente novo entra primeiro no Storybook, depois na tela.

## Seções

- **Fundamentos** — `src/styles.css` (`@theme` do Tailwind) com os tokens do design system
  **VE-360**: cor, tipografia, espaçamento, raio e sombra. As escalas padrão do Tailwind
  (cores, `text-*`, `rounded-*`, `shadow-*`) foram removidas.
- **Componentes** — `src/components/ui/<nome>/`: genéricos, sem regra de negócio
  (`kpi-card`, `data-table`, `filter-bar`…).
- **Layout** — `src/components/layout/`: casca do app (sidebar, header, containers de página).

Componentes de feature (`src/features/<feature>/components`) não entram no catálogo: eles
compõem os de `ui/` com dados da API.

## Regras

- Story ao lado do componente: `src/components/ui/<nome>/<nome>.stories.tsx`, com o
  `title` na seção certa (`Componentes/KpiCard`).
- Estilo só por tokens do `@theme` (classes do Tailwind geradas a partir deles); nada de
  cor ou espaçamento solto no componente.
- Toda story cobre os estados que a tela vai usar: padrão, carregando, erro e vazio.
- Tema claro não vira story separada: use o seletor **Tema** na barra do Storybook (vale no
  canvas e nos exemplos das páginas de docs). O painel Accessibility deve passar nos dois.
- O painel **Accessibility** precisa ficar sem violações.
- Sem biblioteca de componentes como dependência. Componentes do
  [shadcn/ui](https://ui.shadcn.com/) (estilo `base-nova`, sobre Base UI) entram por `npx shadcn@latest add <nome>`: a CLI gera
  `src/components/ui/<nome>.tsx`; mova para `ui/<nome>/<nome>.tsx` com `index.ts` e troque
  as classes do shadcn (`primary`, `ring`, `opacity-50`, `shadow-xs`…) pelos tokens do
  VE-360. Exemplo: `ui/button`. Componentes do [interior.dev](https://www.interior.dev/)
  usam a mesma CLI com a URL do registro (`npx shadcn@latest add
  https://www.interior.dev/r/<nome>.json`, que gera `src/components/interior/`) e seguem o
  mesmo caminho até `ui/`. Exemplo: `ui/hold-to-confirm`.
- Ícones só de `@phosphor-icons/react`; tamanho, peso, cor e acessibilidade em
  **Fundamentos/Ícones**.
- Componente com `Link` do router (app-sidebar, app-shell): declare a rota atual em
  `parameters: { rota: "/receita" }`; o `preview.tsx` monta um router de memória com ela.

## Modelo de story

```tsx
// src/components/ui/kpi-card/kpi-card.stories.tsx
import type { Meta, StoryObj } from "@storybook/react-vite";
import { formatBRL } from "#/lib/format";
import { KpiCard } from "./kpi-card";

const meta = {
	title: "Componentes/KpiCard",
	component: KpiCard,
	tags: ["autodocs"],
} satisfies Meta<typeof KpiCard>;

export default meta;
type Story = StoryObj<typeof meta>;

export const Padrao: Story = {
	args: { label: "Receita faturada", value: 45_712_401.17, format: formatBRL },
};
export const Carregando: Story = {
	args: { ...Padrao.args, value: undefined, loading: true },
};
```

## Previstos (V2-02)

`SeriesChart` e `FilterBar`.

Prontos: `DataTable` (**Componentes/DataTable**): ordenação com as linhas viajando até a
nova posição (Sortable Table do interior.dev), paginação, seleção múltipla, lista de cards
em container estreito e os estados de carregando, erro e vazio. `RegionMap`
(**Componentes/RegionMap**): mapa da RMR que escolhe município e bairro, com zoom e
enquadramento animados. `Breadcrumb` e `DropdownMenu` (shadcn/ui) para a trilha do recorte no topo.
`Modal` (**Componentes/Modal**, Modal do interior.dev): decisão curta que interrompe a tela, com
foco preso, Esc e fundo para fechar e entrada em mola; consulta longa continua no `Sheet`.
`FloatingLabelInput` e `FloatingLabelTextarea` (**Componentes/FloatingLabel**, Floating Label
do interior.dev): o rótulo sobe para um espaço reservado acima do texto em vez de sumir.
`WaterfallChart` (**Componentes/WaterfallChart**): ponte horizontal do total inicial ao final,
com alta em `success` e queda em `danger` (o sinal do valor diz o mesmo sem a cor), o acumulado
de cada etapa como trilho em `pressed` e degraus contínuos entre as etapas; no total final, a
variação líquida aparece na barra (alta preenchida, queda só contornada), com a conta no tooltip
(`compareLabel`); eixo ampliado com corte nas barras de total quando o zero fica longe, barras
que deslizam ao trocar de dados e uma tabela por baixo para o leitor de tela; abaixo de 28rem de
container, o valor sobe e a barra ocupa a largura toda.
`KpiCard` (**Componentes/KpiCard**): rótulo, número e variação, nesta ordem. A unidade sai em
`font-sans` menor ao lado do número em `font-display`; a variação leva seta e sinal, com
`favorable` dizendo se alta é boa (`"up"`, padrão), ruim (`"down"`: DEC, FEC, perdas) ou só
informativa (`"none"`). `hint` abre a definição da métrica; `link` torna o card inteiro
clicável; `highlight` põe o número em `accent-text` (um por região). Abaixo de 16rem o valor
desce para `text-title`. `KpiValue` e `KpiDelta` são exportados para compor fora do card. Para
números grandes, `formatBRL(v, { compacto: true })` → "R$ 45,7 mi".
